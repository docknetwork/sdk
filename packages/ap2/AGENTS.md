# ap2

## Purpose

Implements [AP2](https://ap2-protocol.org/) mandate and receipt issuance/verification as compact
ES256 SD-JWTs/JWTs, built on `crypto-utils`.

## Entry Point & Stack

- Entry: `src/index.js`, `types: dist/types/index.d.ts` (see `package.json` `exports`).
- Check `package.json` for the current version. Depends on `@docknetwork/crypto-utils` (pinned
  exact version — check `package.json`) and `ajv` for schema validation.

## Non-obvious mechanisms

- `src/schemas` holds JSON schemas generated by the `generate-schemas` script
  (`node scripts/generate-schemas.mjs`) — regenerate rather than hand-editing files under
  `src/schemas` if the mandate/receipt shape changes.
- The two `example:*` scripts (`example:receipt`, `example:did-mandate`) each run `yarn build`
  first, then execute a real example script under `examples/` — use them to sanity-check an API
  change end-to-end, not just via unit tests.

## Local commands

```bash
cd packages/ap2
yarn build                 # build:js (rollup) + build:types (tsc -p tsconfig.build.json)
yarn generate-schemas       # node scripts/generate-schemas.mjs
yarn test                   # jest --runInBand
yarn example:receipt        # build + run examples/issue-and-verify-receipt.mjs
yarn example:did-mandate    # build + run examples/verify-mandate-with-did-user-key.mjs
yarn lint
```

## Tests

Jest suites under `tests/` (`mandates.test.js`, `receipts.test.js`, `signer.test.js`,
`utils.test.js`). CI (`.github/workflows/ap2-tests.yml`) runs `turbo run build test --filter
@docknetwork/ap2` — build is a prerequisite of the test job here, unlike packages where `test` runs
against source directly.
